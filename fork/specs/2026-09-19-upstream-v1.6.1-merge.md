## 判断が必要な点

### うちの PR #2 が upstream に巻き戻される

PR #2（`cd367b9`）は「group member の logo に `GROUP_MEMBER_INDENT`（ZWSP + 2桁）を
前置するのをやめた」。upstream v1.6.1 はこの前置を**残している**（`src/herdr.rs:1485`）。
H3 で upstream を採ると、うちの修正は消える。

両者の主張は正面から食い違う:

- うち: group 行が畳まれると行リストが1つ上へ詰まるので、logo 行は head でも member でも
  continuation 行。Herdr が既に3桁下げているところへ更に2桁足すと2桁ずれる。
  **group header と logo の間にユーザー行がある時だけ出る**（`build_managed_rows` がそれを保持する）
- upstream: head の continuation 行は Herdr が hang-indent するが member はしないので、member には前置が要る

どちらが正しいかは**この機械の Herdr のバージョンと sidebar 行設定で決まる**ので、机上では決まらない。
方針: **まず upstream をそのまま採り、実機のサイドバーを見る**。2桁ずれが再発したら
upstream の新しいコードパス（`apply_group_and_icon` の `member` 分岐）に対して PR #2 を
当て直し、その時に upstream へ issue を出す。

### 16 トークン予算

`metadata_report_names` は Herdr の 16 トークン上限で名前を捨てる。upstream は
`quota_share_*` を捨てない側に足したが、うちの `quota_week_scoped_*` は
`ROWS_THAT_MUST_NOT_LAG` に**入っていない**。Claude ペインのトークンが増えると
scoped 週次の行が1リフレッシュ遅れる可能性がある。マージ後に実機で見て、遅れるなら
`ROWS_THAT_MUST_NOT_LAG` に足す。

## ロールバック

作業前に `dev` の現在地へタグを打つ:

```bash
git -C /home/hadas/projects/herdr-agent-quota tag fork/pre-v1.6.1 dev
```

Herdr 側の設定は `configure` が書き換えるのでバックアップを取る:

```bash
cp ~/.config/herdr/config.toml ~/.config/herdr/config.toml.pre-v1.6.1
cp ~/.config/herdr/plugins.json ~/.config/herdr/plugins.json.pre-v1.6.1
```

戻し方は段階ごとに違う:

| どこで壊れたか | 戻し方 |
| --- | --- |
| マージ中（未コミット） | `git merge --abort` |
| コミット後・push 前 | `git reset --hard fork/pre-v1.6.1` |
| ビルド後・見た目が壊れた | `git reset --hard fork/pre-v1.6.1` → `./install.sh` |
| サイドバーの設定が壊れた | 上に加えて `config.toml.pre-v1.6.1` を戻して Herdr を再起動 |
| 古いビルドがキャッシュを読めない | `rm -f ~/.local/state/herdr/plugins/herdr-agent-quota/*.json` してから refresh を**1回** |

`dev` は検証が終わるまで push しない。`fork/sync.sh` は merge の直後に push するので、
今回は使わず手で進める。
